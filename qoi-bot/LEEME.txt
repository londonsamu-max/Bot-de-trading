BOT Q OI v0.4 — todo por código
================================

Qué hace
- Abre Quantium en un Chrome propio del bot, carga la máquina (reglas A, C, D, E, corredor, apertura) sobre SPX y QQQ,
  y manda las señales de MES y MNQ a una o varias cuentas por webhook de TradersPost.
- Calcula solo el ratio MNQ/QQQ cada mañana, guarda todo en registros/qbot_FECHA.csv y se cierra a las 16:10 NY.
- El token de Quantium no sale del navegador: el programa solo recibe las señales ya calculadas.

Instalación (una vez, en la terminal, dentro de esta carpeta)
  1. Instala Node.js 18 o superior (nodejs.org).
  2. npm install
  3. npx playwright install chromium
  4. npm run login          -> se abre Quantium: inicia sesión y cierra la ventana.
  5. npm run instalar-horario -> arranca solo de lunes a viernes a las 8:20 (hora del computador).
  Para probar ya mismo: npm start   (Ctrl+C para detener)

Cuentas (config.json -> "cuentas")
- Cada cuenta es una estrategia de TradersPost conectada a un bróker de futuros o a una empresa de fondeo,
  con su propio webhook, riesgo por operación y máximo de contratos.
- El bot manda la misma señal a todas las cuentas activas y ajusta el tamaño al riesgo de cada una.
- Antes de activar una cuenta de fondeo, confirma por escrito con la empresa que permite operar con bots.

Papel / demo
- "modo": "papel"  -> no envía nada, solo registra (así viene).
- "modo": "demo"   -> envía a las cuentas con "activa": true y webhook puesto.
- El programa relee config.json en cada señal: volver a "papel" corta los envíos al instante.

Requisitos
- Computador encendido con tu sesión abierta a la hora de arranque.
- Quantium Premium. Revisa los términos de Quantium y de tu empresa de fondeo sobre automatización.
- Contratos: MESZ2026 y MNQZ2026 vencen en diciembre; cámbialos en config.json al hacer el roll.

Desinstalar el horario: node instalar-horario.js --quitar

Modo sin navegador (runner.js) — es el que usa el horario
- Corre el mismo bot.js dentro de Node, sin abrir Chrome, pidiendo los datos a la API de Quantium con un token.
- Token: ~/.qoibot-token.json (la sesión copiada de localStorage) y ~/.qoibot-supabase-key. Se renueva solo.
- Probar token y API:  node runner.js --probar
- Si el registro dice "sin sesión válida": copia un token nuevo con
  copy(localStorage.getItem('sb-euwdfoswzwsqrknnvjvj-auth-token')) en la consola de Quantium,
  luego  pbpaste > ~/.qoibot-token.json  y  node runner.js --probar
- La versión con Chrome sigue disponible:  npm start

MetaTrader 5 (Pepperstone demo) — sin TradersPost
- Cuenta en config.json con "tipo": "mt5". MES -> US500, MNQ -> NAS100; lotes = riesgoUSD / (stop × usdPorPuntoLote).
- Necesita MT5 abierto con UN solo EA SpotGammaBridge en un gráfico, Algo Trading activo y US500 en Observación del Mercado.
  Parámetros del EA: InpMaxLotSize 50, InpOrderPollMs 100.
- Solo opera si la cuenta es DEMO y solo cierra las posiciones que abrió el bot (registros/mt5_tickets.json).
- Probar: node mt5-probar.js   (estado)   ·   node mt5-probar.js --orden   (0.1 lote US500 y cierra)

Ver y comprobar rápido
- npm run ver      -> lo que hace el bot en vivo (Ctrl+C para salir; el bot sigue corriendo)
- npm run probar   -> token de Quantium + API + estado de MT5, en segundos
- Cada orden, fallo, apagado o problema de sesión llega como notificación del Mac ("Bot Q OI").
- El bot revisa Quantium cada pollMs (config.json, 2000 = 2 s); la orden llega a MT5 en ~0.2 s.
- Mientras corre, el Mac no se duerme (caffeinate). Si MT5 está cerrado a las 8:20, el bot lo abre.

Registro de niveles (estudio; no opera)
- El bot anota cada llegada del precio a un nivel (calls, puts, gamma, flujo, DEX/charm, de qué lado llega y si
  rebotó o rompió 8 pts en 60 min) y cada cambio de flujo en barras parejas y altas, en registros/niveles/niveles_FECHA.jsonl.
- npm run niveles              -> tablas con todo lo registrado (en vivo + historial)
- npm run niveles-historial    -> rehace el historial con los días de registros/cache (correr después de npm run backtest)
